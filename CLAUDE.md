## Agent skills

### Issue tracker

Issues and specs are local markdown files under `.scratch/<feature>/`. `.scratch/` is git-ignored and never committed, so it exists only on the machine that wrote it. See `docs/agents/issue-tracker.md`.

Build tickets: `.scratch/pw-feel-build/issues/` (`/implement 01` means `pw-feel-build/issues/01-*`); `.scratch/mgs-feel-build/issues/` holds the older ones (tickets 11–14 are superseded; 01, 04, 09, 10 still stand per ticket 09 of the pw-feel map). Each ticket is self-contained; its `**Spec:**` line leads to the decision ticket in `.scratch/pw-feel/issues/`, so open it only when the build ticket leaves a question open.

`.scratch/pw-feel/map.md` is the active map (Peace Walker feel); it overrides `.scratch/mgs-feel/` and `.scratch/area-redesign/` where they disagree.

`.scratch/ghost-layer/`, `.scratch/ghost-layer-build/`, `.scratch/polish/` and `.scratch/polish-build/` are finished history; read them only when asked. `.scratch/area-redesign/` supersedes build tickets 25, 26, 30, 31 for Area layout; read its map before touching them.

Default five-role vocabulary (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

## Project layout

Godot 4.7, organized by feature, each scene next to its script, snake_case. Create folders only when needed.

Where things live:
- `ai/`: Aigis, Glaukopis, HQ polls, mission tally. Node-free so it's testable; `docs/adr/0001` governs Aigis.
- `actors/guard/`: `guard_alert.gd` (alert state machine), `guard_vision.gd`, `bt/` + `guard_tree.tres` (LimboAI tree); the Guard node is an `extends` chain, `guard.gd` → `guard_downs.gd` → `guard_moves.gd` → `guard_body.gd`. `actors/operative/`: player (`operative.gd` → `operative_hands.gd` → `operative_body.gd`), items, weapons, `locomotion.gd`.
- `missions/`: `campaign.gd` (every Mission as data), `mission_run.gd`, `deployment.gd`.
- `areas/<area>/<area>.tscn` is generated by `tools/build_<area>.gd` (`godot --headless --path . --script tools/build_harbour.gd`); change the data in the tool (the Core's is sliced into `tools/core/zone_*.gd`) and rebuild, never hand-edit the scene. Builders extend `tools/area_builder.gd` → `area_dressing.gd` → `area_kit.gd`. Reworking an Area's layout goes through the `level-pass` skill (`.claude/skills/level-pass/`).
- `audio/`: `mix.gd` (autoload `Mixer`: buses, music state, hit-stop, SFX), `voice_blip.gd` (text blips). Node-free rules live in `ai/` (`music_state.gd`, `alert_beat.gd`).
- `ui/<feature>/`: hud, radio, briefing, pause, post_mission, psx_look, debug_overlay.
- `tests/test_<module>.gd`: godot_ai suites, run with the `test_run` MCP tool, or `godot --headless --path . tools/run_tests.tscn` as the fallback runner. `docs/deployment-tables.md` is generated by `tests/test_aigis.gd`.

Keep our scripts near 500 lines; the pre-commit hook rejects one past 600 (`addons/` is exempt). Split along a real seam (an `extends` chain, a helper the file owns), not at a count.

After adding a `class_name` run `godot --headless --path . --import` before the suite, or other scripts fail with "Identifier not declared".

`docs/mechanics-map.md` maps each mechanic (Takedown, Scanner cones, Alert chain, Aigis, HUD…) to its file and test suite; open it before grepping for where a mechanic lives.

`docs/GUIDE.md` has the asset flow and full folder tree.

- Raw downloads go in `_raw/` (ignored by git and Godot); copy only the files you use into `assets/`.
- Every third-party asset gets a line in `docs/CREDITS.md`: name, author, link, license.

## Commits

Use [Conventional Commits](https://www.conventionalcommits.org/): `<type>[optional scope]: <description>`, then an optional body and optional footer(s). Common types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`. Planning changes (map, tickets, research) are `docs(ghost-layer)`. Throwaway prototypes use `feat(prototype)` on their `prototype/<name>` branch.

Branches are `<type>/<kebab-name>` named after the work, never the ticket: `feat/guard-alert-chain`, not `feat/05-guard-alert-chain` or `fix/issue-12`. Ticket numbers stay out of branch names and commit headers.

`.githooks/commit-msg` enforces both rules. Enable it once per clone with `git config core.hooksPath .githooks`.

The tree often mixes several pieces of work: commit only yours, by hunk, with `python tools/stage_hunks.py <file> <regex>` (`-n` lists the hunks first). `.githooks/pre-commit` runs the suite on the staged content in a temp checkout, so unstaged edits don't affect it.
