## Agent skills

### Issue tracker

Issues and specs are local markdown files under `.scratch/<feature>/`. See `docs/agents/issue-tracker.md`.

Build tickets: `.scratch/ghost-layer-build/issues/` (`/implement 01` means `ghost-layer-build/issues/01-*`). Each ticket is self-contained; its `**Spec:**` line leads to a spec index, so open one section file only when the ticket leaves a question open.

`.scratch/ghost-layer/` (map, decision tickets, research) is finished design history; read it only when asked. `.scratch/area-redesign/` supersedes build tickets 25, 26, 30, 31 for Area layout; read its map before touching them.

### Triage labels

Default five-role vocabulary (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `GLOSSARY.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Project layout

Godot 4.7, organized by feature, each scene next to its script, snake_case. Create folders only when needed.

Where things live:
- `ai/`: Aigis, Glaukopis, HQ polls, mission tally. Node-free so it's testable; `docs/adr/0001` governs Aigis.
- `actors/guard/`: `guard_alert.gd` (alert state machine), `guard_vision.gd`, `bt/` + `guard_tree.tres` (LimboAI tree). `actors/operative/`: player, items, weapons, `locomotion.gd`.
- `missions/`: `campaign.gd` (every Mission as data), `mission_run.gd`, `deployment.gd`.
- `areas/<area>/<area>.tscn` is generated by `tools/build_<area>.gd` (`godot --headless --path . --script tools/build_harbour.gd`); change the data in the tool and rebuild, never hand-edit the scene.
- `audio/`: `mix.gd` (autoload `Mixer`: buses, music state, hit-stop, SFX), `voice_blip.gd` (text blips). Node-free rules live in `ai/` (`music_state.gd`, `alert_beat.gd`).
- `ui/<feature>/`: hud, radio, briefing, pause, post_mission, psx_look, debug_overlay.
- `tests/test_<module>.gd`: godot_ai suites, run with the `test_run` MCP tool. `docs/deployment-tables.md` is generated by `tests/test_aigis.gd`.

`docs/GUIDE.md` has the asset flow and full folder tree.

- Raw downloads go in `_raw/` (ignored by git and Godot); copy only the files you use into `assets/`.
- Every third-party asset gets a line in `CREDITS.md`: name, author, link, license.

## Commits

Use [Conventional Commits](https://www.conventionalcommits.org/): `<type>[optional scope]: <description>`, then an optional body and optional footer(s). Common types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`. Planning changes (map, tickets, research) are `docs(ghost-layer)`. Throwaway prototypes use `feat(prototype)` on their `prototype/<name>` branch.

Branches are `<type>/<kebab-name>` named after the work, never the ticket: `feat/guard-alert-chain`, not `feat/05-guard-alert-chain` or `fix/issue-12`. Ticket numbers stay out of branch names and commit headers.

`.githooks/commit-msg` enforces both rules. Enable it once per clone with `git config core.hooksPath .githooks`.
